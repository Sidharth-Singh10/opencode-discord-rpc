# M0 — packaged-host and transmission spike

Status: **implemented and exercised on the packaged artifact**. Gate result:
**PASS for the M0 spike**, with the remote-endpoint test **blocked** (no genuine
authorized remote server existed) and the Discord **visual check left to the
user**. Nothing was published to npm.

This document records only what was observed in the lab. It is not a claim that
every event type or delivery mode exists.

## What M0 is

A TUI-only package that:

- loads from an isolated `cli.json` on OpenCode **2.3.0**;
- probes the host runtime (`node:net`, `bun:sqlite`, `node:sqlite`);
- records an allowlisted, bounded event capture;
- owns one fixed Discord presence payload and one explicit Unix socket;
- arbitrates one publisher across terminals with a SQLite lease and persistent
  fence;
- publishes only on an explicit `/presence-m0 publish` command with `live:true`.

It is not the production state machine, renderer, session election, daemon or
transport-hardening layer.

## Reproduction

All commands below use a fresh lab. Replace the paths and the password
placeholder; the tested lab used `/tmp/opencode/discord-rpc-m0.o5vSJ6`.

```bash
cd /home/levi/opencode-discord-rpc
LAB="$(mktemp -d /tmp/opencode/discord-rpc-m0.XXXXXX)"
mkdir -p "$LAB/pack" "$LAB/xdg-config/opencode" "$LAB/work" "$LAB/evidence" "$LAB/runtime"

bun run typecheck
bun test
bun run build
npm pack --json --pack-destination "$LAB/pack" > "$LAB/pack.json"
TGZ="$LAB/pack/opencode-presence-discord-0.0.1.tgz"
sha256sum "$TGZ"
tar -tzf "$TGZ"

npm install --prefix "$LAB/xdg-config/opencode" --ignore-scripts --no-audit --no-fund "$TGZ"
```

`$LAB/xdg-config/opencode/cli.json` points at the **expanded installed package
directory** (not the repo, not a link):

```json
{
  "plugins": [
    {
      "package": "<LAB>/xdg-config/opencode/node_modules/opencode-presence-discord",
      "options": {
        "m0": {
          "capture": true,
          "live": false,
          "evidenceDir": "<LAB>/evidence",
          "runtimeDir": "<LAB>/runtime"
        }
      }
    }
  ]
}
```

Lab terminals:

```bash
export XDG_CONFIG_HOME="$LAB/xdg-config"
export OPENCODE_DB="$LAB/opencode.db"
export DISCORD_IPC_PATH=/run/user/1000/discord-ipc-0
unset OPENCODE_CLI_CONFIG_CONTENT
export OPENCODE_PASSWORD='<lab server password>'

opencode serve --hostname 127.0.0.1 --port 43173
opencode --server http://127.0.0.1:43173 "$LAB/work"   # one terminal per instance
```

The lab server is dedicated to the experiment; the user's shared service and
`~/.config/opencode` are never touched. A fixed `OPENCODE_PASSWORD` is needed
for the two clients and for the permission/form helper.

Commands inside the TUI:

```text
/presence-m0 snapshot
/presence-m0 publish
/presence-m0 disconnect
```

`publish` refuses unless `m0.live` is `true`, the editor route or a live event
has identified a session, the executed model is observable, and a session user
message creation time exists. Startup time and publish time are never
substituted.

### Evidence validation

```bash
bun run scripts/m0-evidence.ts "$LAB/evidence"
```

`data.listen` saw 2, the reference stream saw 6. After the server restart the
reference observer did not emit a new `server.connected`, while the TUI stayed

`server.connected` at this stage.

### Timestamp provenance and freeze

- Source field: `session.message.list[].type=user.time.created`
- Original units: milliseconds since the Unix epoch
- Conversion: `floor(ms / 1000)`, validated as a safe integer ≥ `1e9` and not
  more than 5 minutes in the future
- Frozen per session **per process** on first successful publication
- Re-publish after 5–12 s sent the same `1794981213`
- After a fenced takeover, the new instance recomputed from the same latest
  user message and sent the same `1794981213`. This worked because no new user
  message arrived; the freeze is not shared through the coordination DB.

No user message means no publication; the plugin records a refusal instead.
Startup time and publish time are never substituted.

## Ownership and fencing (spike question 5)

Coordination store: `<runtimeDir>/publisher.sqlite`, directory mode `0700`,
regular file owned by the current user, no symlink. The fence lives in `meta`
and only increases; releasing never resets it.

Observed live sequence:

```text
fence 1 acquire 322e0672  (first TUI)
fence 1 release 322e0672  (reload)
fence 2 acquire 22201d4d  (same PID, new setup generation)
fence 2 release 22201d4d  (restart into live mode)
fence 3 acquire 89e3b3ea  (live TUI 1)
fence 4 takeover 6655f5fa previous 3  (live TUI 1 SIGSTOPped)
       revoke   89e3b3ea fence-changed
fence 4 release 6655f5fa  (explicit disconnect)
fence 5 acquire 6655f5fa  (publish after reconnect)
fence 5 release 6655f5fa  (final disconnect)
```

- Two instances were live at once; only the fence holder connected and
  published. The other recorded `contended` every 2 s without freezing the TUI.
- `SIGSTOP` of the owner for >10 s let the waiter take over at ≈10–11 s
  (`takeover` with `previousFence`), incrementing the fence.
- `SIGCONT` made the old owner observe the changed fence, revoke itself,
  destroy its Discord connection, and refuse a clear.
- A signal cannot be observed while a process is stopped; the guarantee is
  no **new** enqueue by a revoked owner. Bytes already handed to the OS are
  outside the claim.
- Holding `BEGIN IMMEDIATE` while `SIGSTOP`ped blocks takeover even after the
  stale window. `test/m0-process.test.ts` proves that the waiter stays
  `contended` and the resumed owner completes safely; it also covers
  `kill -KILL`.
- `/reload` re-ran `setup`: a new instance and generation appeared, the old
  lease was released and fence 2 was acquired. This is recorded, not assumed.

## Privacy

The capture record is assembled field by field, never by serializing an event,
context or session. It contains only:

- event type, observation sequence/time, pseudonymized event/session/location
  identifiers, and an instance ID;
- structural field paths and primitive types (stopping at containers such as
  `input`, `content`, `error`, `metadata`, `native`, `resources`, `fields`,
  `text`);
- explicit allowlisted primitives: status type, attempt, interruption reason,
  compaction reason, permission reply type, selected model/agent, executed
  tool flag, and timestamps.

Excluded by construction: prompts, reasoning, deltas, tool input/output,
paths, titles, permission resources/messages, form titles/fields/answers,
error bodies, credentials, URL credentials and arbitrary metadata.

Live canaries (values deliberately seeded; the validator scans all capture
files for exact matches):

| Category | Seeded in | Result |
|---|---|---|
| prompt | user message text | absent |
| tool | shell command output | absent |
| permission | shell command resource path | absent |
| error | failing shell command path/output | absent |
| form | `question` form header/description | absent |

Five canaries, 21 evidence files scanned, **0 leaks**. The reference stream
carries no structure or values at all. Unit tests additionally seed form and
error canaries in synthetic events.

## Limitations and open questions

1. **Remote server test is blocked.** No genuine authorized remote endpoint
   exists here. Identity is recorded as `unknown`, which refuses local-DB
   enrichment; the classifier is unit-tested for local, remote and unknown.
   Do not read this as a passing remote test.
2. **Visual card is unverified.** RPC acknowledgment is not evidence that the
   asset keys resolve or the timer renders. See the visual checklist above.
3. **No `session.idle` / `session.status` events.** M0 uses execution terminal
   events. Any future idle detection needs a new probe and a fallback.
4. **Freeze is per process.** A second instance recalculates on first publish.
   It matched here only because the session's user message did not change.
   Sharing the frozen anchor across instances needs a deliberate decision.
5. **Event-stream reconnect is not proven.** The TUI survived a server restart
   and kept receiving events, but the reference observer did not emit a second
   `server.connected`. Discord reconnect was exercised by disconnect → publish.
6. **Suspend inside the critical section** delays takeover until the holder
   resumes or the OS releases the write lock. Safety is preserved (no
   concurrent writer); liveness is not. This is intentional and tested, but a
   suspended process can hold the card for longer than the stale window.
7. **Capture is a sample**, not a completeness proof. The matrix reports what
   this host delivered in these scenarios; absent types are not claimed.
8. The live TUI test used `SIGSTOP`/`SIGCONT` for revocation. `kill -KILL`,
   critical-section suspend and adversarial pre-write fencing are covered by
   real subprocess tests rather than the TUI run.
9. The `question` form was answered/cancelled through the lab server API; the
   TUI modal race was not used as evidence. The form event and canary
   redaction are still genuine host events.

## Gate result

The packaged TUI host, `node:net`, `bun:sqlite`, event delivery, session
model/agent/cost, a session-anchored integer timestamp and a fenced live
publication are all demonstrated. The M0 spike gate is **PASS** for everything
that this environment could genuinely test. The remote-endpoint criterion is
**blocked**, and the visual card check is handed to the user. Publishing
`0.0.1` to npm remains gated on those two items.
